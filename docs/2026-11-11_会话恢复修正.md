# 1.0.11 会话恢复与隔离验证

根据一轮 17 账号日志，修复票据已由 Steam 状态通知确认失效、且已从本地列表移除时，清理仍报“无法确认本次取消”的问题。只有通知 CRC 与本次票据匹配且通知时间不早于出票时间，才按 already_invalidated 返回，并明确标记 cancelApiCalled=false；无匹配依据时仍保留原错误。

认证失效后的自动重建至少等待 30 秒，界面显示下次尝试时间。原有较短重建间隔下，日志多次出现相隔约 10 秒的连续失效，后一次关联到了新票据。该等待用于降低短时间反复重建风险，不证明失效的外部来源，也不能精确归属 Steam 只带账号 ID 的延迟回调。真实认证失败仍按失败处理。

新增 auth_list_submitted / auth_list_ack，记录遥测添加与清理时实际发送及确认的票据 CRC；新增 cancel_api_call 区分“准备清理”与“实际进入库取消方法”。这些日志不含票据、GC 令牌或登录凭据。

CONTROLLER_TELEMETRY=off 暂停控制端客户端遥测工作器，保留 Steam 游戏租约、插件实体、插件服务器端事件及后台人数采集。该模式用于检验认证失效是否依赖客户端遥测，不以公共人数作为该组实验的成功标准。使用方式见 [诊断说明](POPULATION-DIAGNOSTICS.md)。

插件仍为 2.5.9；已经更新到该版本时本次无需替换插件。保留原有 data，正常停止旧控制端，再替换程序文件启动。

完整测试 77 项：76 通过、0 失败、1 个既有 .NET SDK 地图 helper 测试跳过。42 个 JavaScript 文件语法检查通过，浏览器启动、配对、公共查询、诊断启停、表单、批量动作和手机布局通过。新增测试覆盖已失效票据的幂等清理、无匹配依据不隐藏错误、延迟重建与迟到事件，以及暂停客户端遥测时游戏认证及停止清理仍正常。

新增恢复行为尚未在真实服务器联合验证。当前系统不是完整 Rust 游戏客户端，也没有 EAC 客户端会话；本版没有宣称解决“所有账号持续被公共人数收录”，没有改变公共计数或伪装认证成功。公共人数判定仍需正常客户端对照及上游证据。
