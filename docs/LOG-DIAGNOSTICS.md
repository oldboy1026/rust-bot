# 后端日志诊断工具

2026-10-31，诊断工具修订 1。适用于控制端 1.0.4 的现有 JSONL 日志，控制端核心版本保持 1.0.4。

工具按账号读取请求、响应和清理记录，核对已记录正文的哈希及 UTF-8 字节数。它只读取本地文件，不登录 Steam、不申请票据、不发送网络请求，也不改变事件生成或发送规则。控制端运行中、停止后均可使用。

## 后端处理日志（1.0.7）

后端启动后自动记录到 `data/logs/controller/events.jsonl`，无需运行诊断命令。设置了 `CONTROLLER_DATA_DIR` 时，以该数据目录为准。

记录包括服务启动/停止、Steam 登录状态、分配状态变化、认证失效的标准原因、会话释放原因、核对时实体消失、插件连接中断、地图资料同步状态和公共人数。公共人数在管理页查询时记录首次结果、人数/状态变化及每分钟样本；页面关闭时不另外轮询。`checkedAt` 是查询时间，`sourceUpdatedAt` 和 `cacheAge` 来自上游响应，两者不能混作人数发生变化的精确时刻。

每个运行日志达到约 4 MiB 后轮换，保留当前文件及 4 个备份 `events.1.jsonl` 至 `events.4.jsonl`。每账号遥测日志仍位于 `data/logs/facepunch/`。排查账号时可通过相同的 `accountId`、`assignmentId` 和 `serverId` 对齐两类日志。运行日志不保存票据、密码、配对命令或插件事件的任意原始详情。

自动地图状态会在管理页服务器卡片显示。读取失败会由插件自动重试；需要同时安装 2.5.7 或更新版插件。地图资料成功同步只证明所需资料已取得，不代表平台会把分配账号计入公共人数。

## Windows 直接使用

将补丁中的 `adminlogger-controller` 目录内容合并到现有控制端目录，然后双击 `facepunch-log-audit.cmd`。保留现有 data 目录和配置。

默认读取 `data/logs/facepunch/`，包含每个账号的 `events.jsonl` 与 `events.1.jsonl` 等轮换文件。设置了 CONTROLLER_DATA_DIR 时，读取该数据目录中的同名位置。

结果在窗口显示，并保存到 `data/diagnostics/facepunch-log-audit.json`。再次运行会更新这份摘要，不覆盖原始日志。比较结果会汇总两侧事件类型、数量、字段数和单事件大小；它不修改遥测生成或发送规则。

## 选择一个账号或指定文件

可将某个账号的 events.jsonl 拖到 `facepunch-log-audit.cmd` 上。这样只核对该文件；需要覆盖同一账号的轮换历史时，指定账号目录。

命令行形式，在项目目录运行：

```powershell
node scripts/facepunch-log-audit.mjs
node scripts/facepunch-log-audit.mjs --json
```

参数：

| 参数 | 作用 |
|---|---|
| 第一个位置参数 | 日志文件、单个账号目录或包含各账号目录的 facepunch 日志根目录 |
| --native | 原生 Rust output_log.txt 的路径，用于比较样本的事件类型、字段数量及单事件大小 |
| --output | 自定义 JSON 摘要路径；默认写入 data/diagnostics/facepunch-log-audit.json |
| --json | 将完整的诊断摘要以 JSON 形式打印到窗口 |
| --help | 显示命令用法 |

例如要比较本机当前 Rust 日志：

```powershell
node scripts/facepunch-log-audit.mjs --native 'E:\SteamLibrary\steamapps\common\Rust\output_log.txt'
```

原始客户端日志可能包含票据，不应直接分享。工具的摘要只保留事件类型、数量与大小，不复制请求头、原始正文或错误消息。摘要保留日志目录路径，用于定位对应账号文件，分享前可按需要隐藏路径。

## 如何读结果

| 结果 | 含义及限制 |
|---|---|
| HTTP 2xx | 日志中有成功 HTTP 响应；不证明真实游戏连接、在线维持或公共人数变化 |
| 无响应记录 | 已保留请求记录但没有匹配响应；可能是网络失败、正在进行或历史轮换不完整，不自动判为未发送 |
| 哈希通过 | 日志中的 JSON 正文与记录的原始 JSON 哈希一致；这是日志内部核对，不是独立抓包验证 |
| 哈希不匹配 / 字节数不匹配 | 正文与元数据不自洽，需要保留对应原始日志进一步检查 |
| 无法核验 | 缺少哈希，或正文中含 `[REDACTED]`；脱敏正文无法还原原始发送字节，不能直接判为损坏 |
| 接收前失败 | attempt_failed 记录没有标记已被接收 |
| 接收后清理失败 | HTTP 已接受后发生的清理异常，单独统计，不把上传算作未成功 |
| 清理未确认 | 有清理记录但没有肯定的确认结果 |
| 未记录清理结果 | 当前保留历史里未观察到相应清理记录，不证明票据仍在使用 |
| 未完整写入的末行 | 快照末尾是不完整 JSON，可能读到正在追加的记录，可稍后重跑 |
| 过长行 / 关联上限 | 该部分未完整计入统计；不会悄悄给出全部核验通过的结论 |

单事件 JSON 大小不包括批次数组的外层括号；`uncompressedBytes` 包括完整批次数组，`compressedBytes` 是日志记录的 gzip 长度。不能把三种大小混用。工具不会重新构造压缩后的网络正文。

原生 analytics 日志可能把一个批次分多次打印：先 `[{`，随后 `,{`，最后另行 `]`，中间夹有调用栈。工具逐条识别事件对象，避免漏掉后续追加事件。

传入 `--native` 后，摘要会把原生事件和后端请求正文按类型汇总对照，并列出各自数量、字段数与单事件 JSON 字节数。两份日志未按账号、会话和时间配对；`native_only` 只表示当前样本一侧没有记录，不能证明后端丢弃事件。真实客户端和后端日志可能覆盖不同账号、时间与运行阶段。原生性能字段数会变化；本工具不据此生成或补发事件。

## 资源限制与验证

每个文件按打开时的长度读取快照，以流方式处理。单行上限 16 MiB，超过后丢弃该行并报告；每账号最多关联 100,000 个请求，超出后明确标记部分统计。工具不跟随日志文件或账号目录的符号链接；目录模式只查当前目录及其下一级账号目录，避免扫描无关数据。

新增测试覆盖轮换关联、跨账号相同请求编号、重复记录、网络失败、HTTP 接受后的清理失败、正文哈希、脱敏正文、损坏末行、长行限制、原生逗号追加及摘要不暴露正文中的凭据。运行：

```powershell
node --test test/log-audit.test.js
node --test
node scripts/check.mjs
```
