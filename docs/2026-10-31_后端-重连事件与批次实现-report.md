### 具体行为

- 每个逻辑游戏连接先生成 `server_browser`，六个开关发送为字符串 `"true"` / `"false"`。世界事件取当前地址对应的真实 `mapFilename`、`requiredProps`，缺失时等待配置，状态命令会显示原因。
- 首次性能约 30 秒生成，后续每 10 分钟生成；世界与性能进入默认 5 分钟游戏表发送窗口。此处区分生成时间与上传时间；5 分钟/10 分钟是所沿用调度配置，不是仅由本轮 6 条事件证明的官方固定周期。
- 队列支持多事件，新的性能仅替换未发送的旧性能，浏览和世界事件在失败重试中保留 GUID。最多 64 条、512 KiB，超限保留原队列；独立重试和共同 HTTP 429 退避继续生效。
- 每个分配拥有独立模拟客户端会话；临时游戏恢复保留客户端会话和起点，重新注册游戏连接更新连接标识、递增序号、重置连接时长。仅插件 WebSocket 恢复且原角色仍在时，保留原遥测任务。显式停止后再启动创建新客户端会话并从序号 1 开始。
- 性能支持按来源提供 `map`、`inventory`、`mainmenu` 统计、修改过的设置、硬件/图形/应用配置、GC 次数及整数 `load_times`。配置中的加载耗时只用于该连接首次样本。`world_ts` 使用观测或插件元数据，未知为 `"0"`，不再使用客户端启动时间。
- `inputSource(context)` 可异步返回原始 `{ baseTicks, inputs }` 或 `null`。ticks 和每四个 int32 一组的布局经过校验，后三列原样保留；无记录时不发送空输入请求。默认仍为原有中性模拟，配置 `inputMode:"none"` 可关闭。
- 新增 `facepunch-import-world.cmd`，支持拖入原生日志；仅合并地图元数据，原子替换配置并限制大小。导入不会复制账号、票据、会话 GUID、原始请求头或其他事件正文。

## 实现调用路径

P1，path_type=callflow，关联 E1/E3/E5、F1/F2/F3：分配启动 → 建立或沿用逻辑客户端 → 新游戏注册更新连接标识/序号 → 遥测任务取当前配置 → 浏览事件优先发送 → 世界入队 → 首次性能入队 → 游戏表窗口合并上传 → 失败保留事件并按退避重试。

P2，path_type=callflow，关联 E2/E5、F4：输入定时器 → 可选 inputSource → 无记录则跳过 → 有记录校验 ticks/四列布局 → 独立输入表发送和重试。默认中性模拟与原始输入适配明确区分。

P3，path_type=solve，关联 E3/E4/E5/E6、F5：用户正常客户端采样 → 私有快照及哈希 → 结构/生命周期对照 → 实现与测试 → 仅导入地图元数据 → 空账号启动验证 → 发布源码包。
